# 演示面板怎么用

给人看"mod 起作用了"：一边是实时地图（谁生成了哪块 chunk），一边是服务器的实时曲线和控制按钮，还能一键跑"donor 关 / donor 开"的对比。设计见 `docs/step10-plan.md` 7.1。

**这是演示，不是测量。** 页面上的数字都标"演示，粗测"：这台机器上限核跑，可能有别的测试同时在跑，每组只飞 1 次，不进第 10 步的矩阵和假设表。面板每秒发 2 条 RCON，自己也占一点服务器时间。

## 起来

在一个测试槽位上（比如 `/home/zhenyu/mc-slots/k2`，用它自己的 `docker/.env.test` 和 `docker/.env.local`）：

```bash
scripts/test_config.sh check      # CPU 频率固定了没有（没固定照样能演示，数字更不准）
scripts/test_server.sh up         # 起这个槽位的测试服务器
scripts/demo.sh                   # 起面板，默认端口 8765；换端口：scripts/demo.sh 8766
```

面板只绑 `127.0.0.1`。在自己电脑上用 ssh 转发端口再打开：

```bash
ssh -L 8765:127.0.0.1:8765 <这台机器>
# 浏览器打开 http://127.0.0.1:8765/demo
```

用完 Ctrl-C 停面板，`scripts/test_server.sh down` 关测试服务器。

## 页面上有什么

**顶上的黄条**是要注意的事：

- `worker 的看门狗没关`：worker 容器没有 `MAX_TICK_TIME=-1`，一个 tick 卡满 60 秒就会被杀掉，这时候 donor 会中途掉线（11-09 第 7 步对比里出过这个问题）。fish 的改动进 main 以后就没有这条了。
- `模拟网络：35ms / 20mbit / 1% 丢包`：模拟网络开着。
- `拿不到 …`：某个数据来源出错了（比如没起 coordinator，`/donor status` 不认识），那几张图写"无数据"，其他照常。

**实时曲线**（每秒刷新，最近 15 分钟）：

| 图 | 意思 |
| --- | --- |
| MSPT | 最近 20 个 tick 的平均和最大耗时（毫秒）。虚线是 50 毫秒的上限，超过就掉 TPS |
| TPS | 每秒实际跑了几个 tick，正常是 20 |
| 服务器 CPU | 服务器容器用了几个核（从宿主机的 cgroup 读） |
| 视野虚空率 | 飞行中：假玩家视野里还没就绪的 chunk 占多少 |
| 卡住占比 | 飞行中：假玩家停在没就绪的 chunk 前面等的时间占比（这一秒 / 整轮）。真实玩家就是在这时候看到"世界没加载出来" |
| 实际 / 理想距离 | 飞行中：实际飞了多远 ÷ 一直不卡能飞多远 |
| donor 在线数 | 连着 coordinator 的 worker 个数 |
| 每秒导入的 tile | donor 交回来、写进存档的 tile 数 |
| 每秒丢弃的 tile | 按原因：来晚了（服务器已经自己做了）、碰到别的 donor 世界的 chunk、碰到服务器的 chunk |
| donor 写入时在玩家前方的比例 | donor 写进来的 chunk 有多少在玩家前面（有用）；在身后的说明来得太晚 |

**地图**：正在飞的那一轮，每个 chunk 按谁做完的上色：原版（服务器自己生成）灰绿、导入后服务器接着做完灰紫、donor 按编号分色（导入了还没被服务器做完的）、验证打回红、读盘浅灰。黑点是玩家。

## 按钮

每个按钮都会先弹确认框。同一时间只做一件事，别的按钮这时候会报"正在做：…"。

| 按钮 | 做什么 |
| --- | --- |
| donor 开 | 起 worker、worker2 两个容器，等它们都连上 coordinator，再打开找需求（`/donor demand on`） |
| donor 关 | 关掉找需求（`/donor demand off`），停掉所有 worker |
| territory / deadline / throughput / hedge / waitdonor | 第 7 步的开关，`/donor feature <名字> on|off`。按钮上写着现在是开还是关 |
| 开始飞 | 放一个假玩家（demobot），按选的速度和时长沿一条没生成过的航线飞（第 4 步的飞行场景）。归档在 `artifacts/demo/demo-fly-<时间>/` |
| 停止 | 提前停下这一轮；归档照留，不出汇总 |
| 模拟网络 | 给两个 worker 的出站加 35ms 延迟、20mbit 限速、1% 丢包（`scripts/netem.sh`）。要等 fish 新版的 `netem.sh` 进 main，之前是灰的 |
| 一键 A/B | 见下面 |

## 一键 A/B

用上面选的速度和时长（默认鞘翅 120 秒）：

1. A：换一个全新世界（seed 424242），donor 关，飞一轮。
2. B：再换一个全新世界（同一个 seed），`/donor reset`，donor 开，只开 deadline，飞同一条航线。

两轮地形完全一样，只差有没有 donor。换世界会重启测试服务器，所以一次大约 8～10 分钟；跑的时候别的按钮都不能用。

跑完下面出一张表（卡住时长和占比、实际 / 理想距离、虚空率、就绪 p95、MSPT、服务器 CPU、导入后接着做完的 chunk 数、有效性），三张 A、B 并排的曲线，和两轮的地图回放。

**有效性**：A、B 两轮假玩家都不能在实体 tick 里同步加载 chunk；B 在飞行期间要有 donor 来源事件，起飞前后 worker 的编号不能变（变了说明中途被看门狗杀掉又连上）。不满足的照样显示，标红写明原因。飞行期间别的项目有容器起停，会写在"并发"里。

结果存在 `artifacts/demo/demo-ab-<时间>/`：`ab.json`（两轮汇总、有效性、并发、参数）、`README.md`（写明"演示，粗测"）、`A/`、`B/`（两轮的完整归档，`layer2.csv` 等和第 4 步一样）。
